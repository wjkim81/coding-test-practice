## 문제: Vehicle Health Score Aggregator

### [Setting]
Sonatus AI Director가 차량 fleet의 *"health score"* 를 실시간으로 추적해. 각 차량은 여러 component에서 health reading을 보냄 (engine: 0.95, battery: 0.78, brake: 0.92 등). 

OEM이 dashboard에 보고 싶은 것:
1. **각 차량의 현재 종합 health score** (component들 가중 평균)
2. **전체 fleet에서 가장 위험한 (lowest health) top-K 차량**
3. **새 reading 들어오면 실시간 업데이트** 

### [Problem]

```python
class FleetHealthTracker:
    def __init__(self, component_weights: dict[str, float]):
        """
        component_weights: {"engine": 0.4, "battery": 0.3, "brake": 0.3, ...}
        Weights sum to 1.0.
        """
        pass
    
    def update_reading(
        self, 
        vehicle_id: str, 
        component: str, 
        health: float  # 0.0 ~ 1.0
    ) -> None:
        """
        Update one component's health reading for a vehicle.
        """
        pass
    
    def get_riskiest_vehicles(self, k: int) -> list[tuple[str, float]]:
        """
        Return top-K vehicles with LOWEST aggregate health score.
        Sorted ascending by score.
        
        A vehicle's aggregate score is the weighted average of its
        component health readings. Only consider vehicles that have
        readings for ALL components in component_weights.
        """
        pass
```

### [Example]

```python
weights = {"engine": 0.5, "battery": 0.3, "brake": 0.2}
tracker = FleetHealthTracker(weights)

# Vehicle 1 — full readings
tracker.update_reading("v1", "engine", 0.9)
tracker.update_reading("v1", "battery", 0.8)
tracker.update_reading("v1", "brake", 0.95)
# v1 aggregate = 0.9*0.5 + 0.8*0.3 + 0.95*0.2 = 0.45 + 0.24 + 0.19 = 0.88

# Vehicle 2 — full readings, riskier
tracker.update_reading("v2", "engine", 0.6)
tracker.update_reading("v2", "battery", 0.5)
tracker.update_reading("v2", "brake", 0.7)
# v2 aggregate = 0.6*0.5 + 0.5*0.3 + 0.7*0.2 = 0.30 + 0.15 + 0.14 = 0.59

# Vehicle 3 — incomplete (no brake)
tracker.update_reading("v3", "engine", 0.5)
tracker.update_reading("v3", "battery", 0.4)
# v3 incomplete → excluded

tracker.get_riskiest_vehicles(2)
# → [("v2", 0.59), ("v1", 0.88)]
# v3 excluded (missing brake reading)
```

### [Constraints]
- Fleet: up to 1,000,000 vehicles
- Components: up to 20 per vehicle
- `update_reading` 호출 빈도 높음 (초당 수천)
- `get_riskiest_vehicles` 호출 빈도 낮음 (분당 1-2회)

## 실전 mode

너 강점 영역이니까 자신감 가져. 

**Hints**:

1. **자료구조 선택**: 각 vehicle의 component → health 매핑. Nested dict 자연스러움.

2. **Aggregate score 계산**: 매번 다 계산 vs 캐싱? Update / query 빈도 차이 고려.

3. **Top-K**: 어제 배운 `heapq.nlargest` 또는 `nsmallest`. Sort 전체보다 efficient.

4. **Trade-off**: 
   - Reading 들어올 때 aggregate 갱신 → update 비용 ↑, query 비용 ↓
   - Query 시점에 aggregate 계산 → update 빠름, query 느림
   - **Update 빈도 >> query 빈도** 일 때 후자 선호

이 trade-off 고려해서 design 선택하고 commit. 천천히 가도 OK ㅎㅎ
