### 문제: Vehicle Telemetry Buffer with Priority

**[Setting]**
Sonatus Collector AI에서 차량 fleet의 telemetry data를 cloud로 보내. 근데 차량이 항상 연결 안 됨 (터널, 산간 지역 등). **차량에 local buffer** 두고, 연결 회복 시 batch upload.

근데 buffer 가득 차면 오래된 거 버려야 하는데, 일반 FIFO로 버리면 **중요한 event** (사고 detection, hard brake 등) 가 버려질 수 있어. → **Priority 적용**.

**[Problem]**

```python
class TelemetryBuffer:
    def __init__(self, max_size_bytes: int):
        """
        Local buffer on vehicle. When full, evict LOW-priority items first.
        Among same priority, FIFO (oldest evicted).
        """
        pass
    
    def add_event(
        self, 
        event_id: str,
        priority: int,        # 0=low, 1=medium, 2=high, 3=critical
        size_bytes: int,
        timestamp_ms: float,
        data: dict
    ) -> bool:
        """
        Add event to buffer. May evict lower-priority items if needed.
        Return True if added, False if can't fit (even after eviction).
        """
        pass
    
    def flush(self) -> list[dict]:
        """
        Return all events sorted by priority DESC, then timestamp ASC.
        Clear buffer.
        """
        pass
```

**[Example]**

```python
buf = TelemetryBuffer(max_size_bytes=1000)

buf.add_event("e1", priority=0, size=400, ts=10, data={...})  # True
buf.add_event("e2", priority=2, size=300, ts=20, data={...})  # True
buf.add_event("e3", priority=0, size=400, ts=30, data={...})  
# True. Buffer = 1100 → over! Evict e1 (priority 0, oldest). 
# Now 700 bytes. Add e3 → 1100. Wait, still over.
# Actually: evict e1 first → 300. Then add e3 → 700. ✅

buf.add_event("e4", priority=3, size=500, ts=40, data={...})  
# Buffer 700+500=1200 → over. Evict e3 (lowest priority oldest) → 300. 
# Still need space → no more low priority → can't evict critical/medium? 
# Wait, e2 is priority 2 (medium), e4 is priority 3 (critical).
# Hmm, edge case — need to think

buf.flush()
# Returns events sorted by priority DESC, timestamp ASC
```

**[Design questions to think]**

코딩 들어가기 전에 design 결정 몇 개:

1. **자료구조 선택**: priority별 분리? 통합 heap? 시간 기준 sort 어떻게?

2. **Eviction logic 명확화**: 
   - 새 event가 high priority인데 buffer 꽉 차면, lower priority만 evict?
   - Same priority면 oldest first OK
   - 같은 priority만 남았는데 새 event 못 들어가면 reject?

3. **Edge case**:
   - 새 event 자체가 max_size 넘으면? Reject.
   - 새 event priority < buffer 안 모든 거? Reject (높은 거 못 쫓아냄).

**[Constraints]**
- max_size_bytes up to ~10 MB
- Event 수 up to ~10,000
- `add_event` 자주 호출 (초당 수십)
- `flush` 드물게 (분당 1번)
