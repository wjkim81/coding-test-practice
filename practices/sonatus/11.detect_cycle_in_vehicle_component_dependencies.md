## 문제: Detect Cycle in Vehicle Component Dependencies

### [Setting]
Sonatus AI Director가 차량 component dependency graph 관리해. Component A가 B에 의존하면 *"A → B"* 형태. 

예: `transmission → engine` (transmission이 동작하려면 engine 필요)

**문제는**: 잘못된 config 또는 software bug로 **dependency cycle**이 생길 수 있어 (A → B → A 같은 거). Cycle 있으면 system deadlock. 미리 감지해야 함.

### [Problem]
주어진 dependency graph에서 **cycle 존재 여부**를 판단.

```python
def has_dependency_cycle(
    dependencies: dict[str, list[str]]
) -> bool:
    """
    dependencies[A] = [B, C] means A depends on B and C.
    Return True if there's a cycle, False otherwise.
    """
    pass
```

### [Example]

```python
# No cycle
deps1 = {
    "transmission": ["engine"],
    "engine": ["battery", "fuel_pump"],
    "battery": [],
    "fuel_pump": ["battery"],
}
has_dependency_cycle(deps1)  # → False

# Has cycle: engine → fuel_pump → engine
deps2 = {
    "transmission": ["engine"],
    "engine": ["fuel_pump"],
    "fuel_pump": ["engine"],   # ← cycle
}
has_dependency_cycle(deps2)  # → True

# Self-loop도 cycle
deps3 = {
    "engine": ["engine"]
}
has_dependency_cycle(deps3)  # → True
```

### [Constraints]
- Component 수 up to 10,000
- Dependency 총 수 up to 100,000
- Graph는 directed
- 모든 component가 dict의 key (즉 leaf도 빈 list로 등록됨)

## 실전 mode

이거 **Graph cycle detection** — graph 알고리즘의 기본 중 기본이야. 면접 단골.

힌트 미리 줄게 (어제 *"학습 mode"* 였으니 패턴 인식 도와줄게):

**Cycle detection approach 2가지**:

1. **DFS + 3-color (white/gray/black)** — directed graph 표준
   - White: 아직 방문 안 함
   - Gray: 방문 중 (recursion stack에 있음)
   - Black: 방문 완료
   - **Gray node를 다시 만나면 cycle**

2. **Topological sort (Kahn's algorithm)** — in-degree 사용
   - In-degree 0인 node부터 제거
   - 다 제거됐으면 cycle 없음, 남아있으면 cycle

**Directed graph cycle detection은 보통 (1) 이 더 자연스러워**. Undirected graph는 (1) 살짝 변형 또는 union-find.

너 (1) 또는 (2) 골라서 commit하고 시작해.
