## Problem 5 — Find Recurring Sensor Patterns (Medium)

**Context:**

You're processing logs from a CAE simulation pipeline. Each simulation run produces a sequence of integer event codes (representing solver states, convergence events, etc.). You want to detect **recurring patterns** to help diagnose pipeline issues.

### Task

Given a list of integers `events` and an integer `k`, find the **k-length subarray that appears most frequently** in the sequence. Return the subarray and its count. If there's a tie, return the one that appears **earliest** in the sequence.

```python
def most_frequent_subarray(events: list[int], k: int) -> tuple[list[int], int]:
    """
    Find the k-length contiguous subarray that appears most often in `events`.

    Args:
        events: list of integer event codes.
        k:      length of the subarray to look for (k >= 1).

    Returns:
        (subarray, count) where:
            subarray is the most frequent k-length contiguous subarray (as a list).
            count    is how many times it appears.
        If multiple subarrays tie for the highest count,
        return the one whose first occurrence is earliest.

    Edge cases:
        - If len(events) < k: return ([], 0).
        - If k <= 0: raise ValueError.
    """
```

### Examples

```python
most_frequent_subarray([1, 2, 3, 1, 2, 3, 1, 2], k=3)
# Subarrays of length 3:
#   [1,2,3] (at index 0)
#   [2,3,1] (at index 1)
#   [3,1,2] (at index 2)
#   [1,2,3] (at index 3)  ← repeat
#   [2,3,1] (at index 4)  ← repeat
#   [3,1,2] (at index 5)  ← repeat
# Counts: [1,2,3]=2, [2,3,1]=2, [3,1,2]=2  → tie
# Earliest first occurrence: [1,2,3]
# Returns: ([1, 2, 3], 2)

most_frequent_subarray([5, 5, 5, 5], k=2)
# Subarrays: [5,5], [5,5], [5,5] → all the same
# Returns: ([5, 5], 3)

most_frequent_subarray([1, 2], k=3)
# len(events) < k
# Returns: ([], 0)
```

### Requirements

1. Use a sensible data structure (think: hash map / counter).
2. Handle ties correctly (earliest first occurrence wins).
3. Handle edge cases (`len(events) < k`, `k <= 0`).
4. Reasonable time complexity — aim for `O(n)` or `O(n·k)`. Don't do `O(n²·k)`.

### What I'm looking for

- Correct use of `dict` / `collections.Counter`
- Awareness that lists aren't hashable → need to convert to tuple
- Tie-breaking logic
- Edge case handling
